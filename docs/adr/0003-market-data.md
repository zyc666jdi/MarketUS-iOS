# ADR-0003: 行情数据策略——Mock 优先，真实源可选

- **状态**：Proposed
- **日期**：2026-11-03
- **决策者**：@ios-leads（待确认）
- **相关**：`docs/data-sources.md`、`docs/architecture.md`

## 背景

项目需要一个「看起来像美股行情」的数据源，用于开发、演示、测试。硬约束：

1. 仓库是**公开**的，不能提交任何 API Key。
2. Agent 会在 CI 中反复运行测试，不能依赖有配额限制的外部服务。
3. 测试必须**确定性**：同一输入两次运行结果一致，才能做快照与断言。
4. 不要求数据真实，但要求**稳定、可靠、语义像真行情**（买卖价、涨跌幅、盘前盘后、延迟标记）。
5. 未来可能换成真实数据源，不能让业务代码绑定某个厂商。

## 选项

| 选项 | 优点 | 缺点 | 风险 |
| --- | --- | --- | --- |
| A. 公共免费 API 作为默认（Finnhub/Alpaca 等） | 数据真实、接入快 | 需 key、限流、无 SLA、授权限制 | CI 抖动、密钥泄漏 |
| B. 自建 Mock（App 内 + 可选 Docker 服务） | 确定性、离线、零密钥、可注入故障 | 需要自己写（~1 天） | 维护成本低 |
| C. 录制回放（record/replay 真实响应） | 接近真实 | 录制需要 key；数据不可再分发 | 授权问题 |
| D. 只用静态 JSON fixture | 最简单 | 无法测实时/重连/节流 | 覆盖不足 |

## 决策

采用 **B 为主 + C 的思想 + A 作为可选适配器**：

1. **默认 `MockMarketDataSource`**：App 内确定性随机游走，`seed + scenario` 决定输出；
   覆盖 Preview、单元测试、UI 测试。
2. **可选 `Mock Server`**（`Tools/mock-market/`，Python FastAPI + Docker）：
   提供 REST + WebSocket，用于手工 Demo 与集成测试；支持故障注入（超时/429/断连/畸形 JSON）。
3. **可选 `AlpacaMarketDataSource`**：真实 IEX 数据，仅手动触发，代价是 key 与 30 symbol 上限。
4. **领域协议隔离**：Core 只认识 `QuoteFetching` / `QuoteStreaming`，厂商 DTO 不进入业务层。
5. **CI 禁止访问真实网络**，任何真实源调用都不在 PR 门禁中。

## 后果

**正面**

- 公开仓库无密钥，贡献者 clone 即跑。
- 测试与快照完全可复现；故障场景可主动构造。
- 换供应商只需新增适配器，业务代码零改动。
- 无行情授权风险（Mock 数据不入库、不分发真实行情）。

**负面 / 代价**

- Mock 的「真实性」有限，无法发现真实数据的脏数据问题（如拆股、停牌、异常 spread）。
- 需要维护一套 mock 服务与契约；契约变更要同步 mock 与客户端。
- 真实集成只能靠手动冒烟，存在「上线才发现」的风险。

**需要跟进**

- [ ] Phase 2 定义 JSON 契约并写 fixture
- [ ] Phase 2 实现 App 内 mock + 场景
- [ ] Phase 3 实现 Docker mock server 与集成测试
- [ ] 真实源冒烟 job（手动）与切换开关

## 重新评估的触发条件

- 需要真实验收（如行情准确性、交易所规则）
- 引入付费行情授权
- Mock 场景覆盖不足导致线上问题
