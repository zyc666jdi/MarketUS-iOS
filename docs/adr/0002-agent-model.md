# ADR-0002: AI Agent 运营模型——有写权、无合并权

- **状态**：Proposed
- **日期**：2026-11-03
- **决策者**：@ios-leads（待确认）
- **相关**：`AGENTS.md`、`docs/agent-workflow.md`、`docs/merge-policy.md`

## 背景

希望 Agent 自主完成「接 ticket → 实现 feature/bugfix → 代码评审 → 请求人工合并」。
核心矛盾：

- 若 Agent 能合并，任何人都无法保证 main 上代码的质量与合规性，且审计链断裂。
- 若 Agent 只能提建议不能写代码，人力无法被释放，自动化收益接近于零。

需要一条「收益最大、风险可控」的分界线。

## 选项

| 选项 | 自主程度 | 风险 | 人类负担 |
| --- | --- | --- | --- |
| A. Agent 全自动（含合并/发布） | 最高 | 极高：注入、误合并、合规 | 事后救火 |
| B. Agent 写代码 + 开 PR，人类合并（本方案） | 高 | 低：人类是最后一道闸 | 每次合并 ~10 分钟 |
| C. Agent 只写草稿，人类提交 | 低 | 极低 | 几乎无收益 |
| D. Agent 仅在人类指派后工作 | 中 | 低 | 需人工派发 |

## 决策

选择 **B**，并把它固化为**权限约束**而非提示词约定：

1. **Agent 有**：读代码、写分支（`ai/*`）、跑测试、开 PR、评论、打非保护标签、请求人工合并。
2. **Agent 没有**：合并按钮、push `main`、合并审批权、受保护路径写权、新增依赖权。
3. **评审必须独立**：Reviewer 使用新会话与新上下文，只读，不继承实现者推理。
4. **人类只在 6 个点介入**：需求、设计、决策、架构合规、合并、发布（见 `agent-workflow.md` §8）。
5. **失败必须收敛**：3 次尝试 / 90 分钟 / 400 行，任一超限即停下升级，禁止无界重试。

## 后果

**正面**

- 人类时间从「写代码」转移到「判断与合并」，单位时间产出提升明显。
- 任何恶意/错误变更都需人类点击，注入攻击的破坏上限被压到「开一个坏 PR」。
- 审计链完整：ticket → run → PR → review → 人类批准 → 合并。

**负面 / 代价**

- 人类仍需 ~10 分钟/PR 的评审带宽，这成为放量的真实瓶颈（因此有并行上限与每日 12 单）。
- Agent 生成的测试可能「假绿」，需要评审专门检查测试有效性。
- 流程文档（本套 docs）本身需要维护，属于固定成本。

**需要跟进**

- [ ] Phase 1 配置分支保护与 bot 权限（这是本 ADR 的技术落地）
- [ ] Phase 3 用 3 个真实 ticket 验证，并统计一次通过率与人类耗时
- [ ] 每季度评估是否放宽（例如低风险 docs 变更允许自动合并）

## 重新评估的触发条件

- 连续 3 个月零 revert、零安全事故、人工评审 < 5 分钟/PR
- 出现需要「Agent 自动发版」的业务压力
- GitHub 权限模型变化（如原生支持机器人审批隔离）
